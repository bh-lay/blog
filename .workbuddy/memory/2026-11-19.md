## backEnd 新增批量删除评论 API

- 新增 `src/controller/api/comments/batch-remove.ts`：`DELETE /api/comments`，JSON body `{ ids: string[] }`。
  - 权限 `COMMENTS_DELETE`（与单条删除共用）；ids 做非空/上限(500)/ObjectId 合法性校验 + 去重；`deleteMany({_id:{$in:[...]}})`；返回 `{code:200,requested,deleted}`；清 `comment` 缓存。
  - 错误码沿用项目风格：`201` 无权限、`400` 参数错误。
- 路由注册在 `src/router/api/index.ts`。**关键决策**：路径用集合形式 `delete /api/comments`，而非 `/api/comments/batch`，因为 `rest /api/comments/:id` 的 `:id` 会匹配任意单段路径并拦截后者。已用 path-to-regexp 实测两条路由互不冲突。
- 对接文档：`backEnd/docs/api-comments-batch-delete.md`（含鉴权、参数、响应码表、curl/fetch/axios 示例、注意事项），供另一个仓库对接。
- 验证：`npx tsc --noEmit` 通过；`npm run build` 通过，dist 产物已更新（dist 被 .gitignore 忽略，不进提交）。

## friend 列表 API 新增 isShow 筛选参数

- `src/controller/api/moment/friend/list.ts`（`GET /api/moment/friend/`）：读取 query `isShow` 并转为布尔加入 Mongo 查询条件。
  - 不传参 → `params` 为空，展示全部（原行为不变，向后兼容）。
  - 传 `true`/`1` → `isShow:true`；传 `false`/`0` 或其它值 → `isShow:false`。
  - 用 `isShow !== undefined` 判断而非真值判断，避免 `isShow=false` 被误判为未传。
- 前端 `frontEnd/single-page/src/view/friends/index.vue` 目前仍拉全量后本地按 `item.isShow` 分组，未改动（可后续按需切换到服务端筛选）。
